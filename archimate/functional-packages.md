# RS-Python - Functional packages

| Functional package | Description | Functions | Supported services | Components |
|---|---|---|---|---|
| **FP1 - External Data Access** | Search, in read-only mode, the data of the Copernicus ground segment and of the data spaces. rs-server translates the STAC API requests into OData requests to the stations, and the OData responses into STAC items. | Search CADIP raw data sessions<br>Search auxiliary data (AUXIP)<br>Search production products (PRIP)<br>STAC / OData mapping<br>Search CDSE and EarthDataHub | External Data Search | rs-server-cadip, rs-server-adgs, rs-server-prip, rs-client-libraries (CdseClient, EarthDataHubClient), STAC browsers (CADIP, AUXIP, PRIP) |
| **FP2 - Data Staging** | Copy products from the external data sources into the RS-Python object storage, and publish their STAC items in the catalog (OGC API - Processes service, run on a Dask cluster). | Staging job management<br>Parallel asset transfer<br>Write to object storage<br>Catalog publication | Data Staging | rs-server-staging, staging Dask cluster, Dask Gateway, staging flows (rs-workflows) |
| **FP3 - Catalog & Data Management** | STAC catalog of the products managed by RS-Python (raw data, auxiliary data, Level-0 to Level-2 products), stored in PostgreSQL / pgstac, with ownership, fine access rights and data lifecycle. | Collections & items management<br>Spatio-temporal search<br>Ownership & access control<br>Asset download<br>Data lifecycle<br>OData PRIP interface | Product Catalog<br>Product Download & Storage Access | rs-server-catalog, pgstac database (CloudNativePG), STAC browser (catalog), object storage |
| **FP4 - Object Storage Access Management** | Keep the object storage accounts and access policies of the users consistent with their catalog rights, and deliver their personal S3 credentials. | S3 accounts synchronisation<br>Access policy computation<br>S3 credentials delivery<br>Bucket configuration | Product Download & Storage Access | rs-server-osam, OVHcloud API, OVHcloud Object Storage, OSAM operation flows |
| **FP5 - Product Processing** | Run the EOPF DPR processors (Sentinel-1, -2, -3) and the SAFE to Zarr conversion on Dask clusters, through an OGC API - Processes service. | Task table & payload generation<br>Processor execution on Dask<br>Job monitoring & cancellation<br>SAFE / Zarr conversion<br>Quicklook generation | Product Processing | rs-dpr-service, DPR Dask clusters (EOPF CPM and processors), Dask Gateway, processing flows |
| **FP6 - Workflow Orchestration** | Implement, schedule, chain and monitor the processing chains as Prefect flows, on demand or systematically. | On-demand flows<br>Systematic processing<br>Scheduling & work pools<br>Custom flow development<br>Performance indicators | Workflow Orchestration | Prefect server and workers, rs-workflows flows, rs-workflow-deployment, PI database |
| **FP7 - Virtual Environment & User Interfaces** | Per-group workspace and user interfaces to discover the data, call the services and develop the processing. | Interactive notebooks<br>Dask cluster management<br>Client libraries<br>API documentation<br>Product browsing | Virtual Environment | JupyterHub, Dask Gateway, rs-client-libraries, rs-server-frontend, STAC browsers |
| **FP8 - Identity & Access Management** | Authenticate the users and the processing, and authorise each request according to the Keycloak roles. | User authentication<br>API key management<br>Request authorisation<br>User & role administration | Platform Administration & Monitoring | Keycloak, API Key Manager, rs-server authentication (all services), Envoy Gateway |
| **FP9 - Platform Operations & Monitoring** | Deploy, monitor, secure and back up the platform. | Logs, metrics & traces<br>Dashboards & alerting<br>Object storage quota monitoring<br>Security monitoring<br>Backup & restore<br>Infrastructure as code deployment | Platform Administration & Monitoring | Grafana, Prometheus, Loki, Tempo, Alloy, Wazuh, NeuVector, Velero, CloudNativePG, rs-infra-core playbooks, bastion |
